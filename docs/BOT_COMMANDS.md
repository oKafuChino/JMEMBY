# Bot 指令与漫画互动

## 下载与账号

- `/jm ID或链接`：立即获取详情并加入下载队列，不再显示确认按钮。普通群、超级群和私聊都支持；群内可用 `/jm@机器人用户名 ID`。
- 私聊直接发送裸 ID 或链接仍提供预览与确认，旧预览按钮保留原用户、原聊天校验。`/jm` 不创建预览确认记录。
- `/my`：在私聊显示用户 ID、状态、组别、已开通的阅读账号登录邮箱和 `KOMGA_PUBLIC_URL` 服务器地址。保留 `/me` 作为兼容别名。
- `/account`：领取或重试开通阅读账号。已交付的初始密码不会重复显示，`/my` 不会解密、恢复或重置密码。被封禁用户只看到封禁提示，不显示账号详情。
- `/queue`、`/status`、`/cancel`、`/retry`、`/library` 已移除，不再执行原操作。进度与完成结果仍回复到原下载聊天；管理员通过 `/web` 查看和取消任务。失败或已取消的漫画可再次 `/jm ID` 提交。

直接下载仍检查注册、封禁、全局去重以及白名单优先规则；获取详情期间被封禁会拒绝入队。白名单重复提交普通等待任务仍提升原任务，保留原下载者和原通知聊天。

## 新增互动指令

| 指令 | 行为 |
| --- | --- |
| `/report ID` | 举报漫画含不合适内容，持久保存举报并通知配置的全部管理员 |
| `/like ID` | 为漫画点赞，每个用户对同一本漫画只计一次，重复调用显示已有点赞 |
| `/random` | 从当前可阅读的漫画记录中随机推荐一本，不会创建下载任务 |
| `/rank` | 按本站用户点赞数降序列出最多十本漫画，同赞数按漫画入库记录 ID 排序 |

这些指令仅私聊可用，需已注册且未被封禁；普通和白名单用户规则相同。排行榜仅展示至少一赞的作品，暂无点赞或漫画库为空时给出明确提示。推荐附漫画 ID、点赞数和阅读服务器地址。

互动范围为本工具记录的 JM 漫画，要求存在成功完成任务和已入库章节。通过网页移除的漫画立即退出随机推荐和排行；重新成功下载后恢复展示。历史点赞与举报保留，不因移除重置每人每本的次数。外部手动导入 Komga 的漫画不在此范围。

## 举报通知

同一用户对同一漫画只保存一条举报，不重复发送。通知包含漫画标题、ID、举报用户 ID 和举报编号；管理员通过网页“举报管理”审核，可忽略或移除漫画；Bot 仅发送提醒，不提供审核操作。举报不会自动删除漫画，消息已送达也不代表已经处理。

接收者来自 `TELEGRAM_ALLOWED_USER_IDS`。管理员需要先私聊启动 Bot，且不能屏蔽 Bot。举报记录和各管理员的发送状态均存入 SQLite；网络错误、Telegram 限流或管理员暂不可达时延后重试，主控重启后继续。配置中已移除的管理员不会再收到待发通知。Telegram 成功接收后、数据库标记前若进程中断，重试可能带来相同举报编号的重复通知。

## 菜单与升级

启动时刷新默认和私聊的斜杠菜单，群聊菜单只展示 `/jm`；管理员群内回复授权 `/kk`、`/white` 仍有效。新菜单含 `/my`、`/report`、`/like`、`/random`、`/rank`，旧任务操作按钮不再显示。用户发送 `/start` 刷新持久键盘。如果在 BotFather 设置过特定语言或聊天专属菜单，需要清理对应覆盖配置。

本版升级至 schema 13，在点赞、举报与投递记录基础上增加举报审核状态和任务通知标记。网页新批量任务仅在网页查看进度和结果，不再发送 Bot 推送；/jm 任务通知保持不变。更新前备份数据库，更新主控即可，无需升级 Agent；回滚旧版需恢复升级前备份。Telegram 真实投递与界面菜单须在部署环境验证。
