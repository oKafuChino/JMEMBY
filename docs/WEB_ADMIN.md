# Komga Plus 网页管理面板

## Bot 使用限制：必加入频道和群组

侧边栏新增“Bot 使用限制”，默认关闭。管理员在这里配置一个必加入频道和一个必加入群组；启用后，普通用户和白名单用户都必须同时加入两者才能使用 Bot。`TELEGRAM_ALLOWED_USER_IDS` 中的项目管理员豁免，可始终通过私聊 `/web` 修复配置；Telegram 群管理员不等于项目管理员。

1. 将同一个 Bot 加入目标频道和群组，并在两处都设为管理员。
2. 填写两处 Chat ID（负数，超级群/频道通常以 `-100` 开头）或公开 `@用户名`。频道栏不能填群组，群组栏不能填频道或私人聊天。
3. 公开聊天留空加入链接时自动生成；私有聊天必须填写对应的 `https://t.me/+...` 或 `https://t.me/joinchat/...` 邀请链接。系统校验链接格式，无法验证邀请链接是否过期或是否属于目标聊天，请管理员自行确认。
4. 点击“验证并保存启用”。主控通过 Telegram 验证聊天类型与 Bot 管理员身份后，原子保存配置并立即生效；校验失败保留原配置。
5. 用户未加入时收到缺少的频道/群组加入按钮；加入后重新发送原指令即可。申请加入需审核通过，仅提交申请不算已加入。

每次允许的 Bot 消息和按钮操作都会重新核验，不缓存“已加入”结果；退出任意一处后下次操作被拒绝。`member`、`administrator`、`creator` 视为已加入；`restricted` 仅在 `is_member=true` 时放行；`left`、`kicked` 不放行。Bot 失去管理员权限、Telegram 限流、网络或超时错误均暂不放行，并提示联系管理员或稍后重试，不暴露内部异常。成员查询规则参见 [Telegram getChatMember](https://core.telegram.org/bots/api#getchatmember)。

限制覆盖注册、阅读账号、个人资料、下载、点赞、举报、推荐、排行和旧确认按钮；群聊仍仅支持 `/jm` 及管理员 `/kk`、`/white`。加入要求不会替代原有注册、邀请码、封禁和确认按钮归属检查，也不会取消已有任务或撤销 Komga 账号。网页批量下载由管理员发起，不受加入限制影响。

“关闭限制”无需 Telegram 在线或重新核验，关闭后保留已保存配置。配置存于现有 SQLite `settings` 表，主控重启后保留，数据库版本仍为 schema 14；只需更新主控，无需更新 Agent。接口 `GET/POST /api/membership` 仅管理员可用，写入沿用 Origin 与 CSRF 校验。退出网页会清空当前页面中的加入链接。

侧边栏提供“节点管理”：管理员可添加、编辑、启停、删除下载节点，查看在线状态、当前漫画及章节进度，并直接生成可复制的一键安装命令。每台 VPS 同时处理一本漫画。创建或编辑节点时可选择“服务队列”：两者（白名单优先）、仅普通队列、仅白名单队列；节点列表显示当前选择。新节点和升级后的已有节点默认服务两者。保存后从下一本漫画开始生效，正在下载的漫画继续完成，无需重启或重新安装 Agent。指定队列没有可领取任务时节点空闲，不会自动领取另一队列；如果没有在线节点服务某个队列，该队列任务继续等待。远程下载始终启用，首次使用需配置 Agent HTTPS 入口，安装器支持 Debian/Ubuntu/Alpine 原生服务，详见 [多 VPS 下载与网页安装](DISTRIBUTED_DOWNLOADS.md)。

面板提供用户与任务统计、注册/邀请码开关、用户组展示、封禁/解禁、双队列分页查看、取消任务及漫画下载来源查询。资格授权和白名单设置仍使用群聊回复命令 `/kk`、`/white`。

## 启用

在 `.env` 设置：

```dotenv
WEB_ENABLED=true
WEB_PORT=8080
WEB_PUBLIC_URL=https://admin.example.com
```

同步代码后执行 `docker compose up -d --build --no-deps app`。Compose 将端口绑定至 VPS 的 `127.0.0.1:8080`，需在 VPS 上用 HTTPS 反向代理转发至该地址。域名应专用于面板，不能带路径、查询参数或尾部路径。例如 Nginx 已配置证书的 server 内：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
}
```

不使用公网域名时，可设置 `WEB_PUBLIC_URL=http://localhost:8080`，电脑执行 `ssh -N -L 8080:127.0.0.1:8080 user@vps`，浏览器打开 `http://localhost:8080`。浏览器地址必须与 WEB_PUBLIC_URL 完全匹配。非 Docker 启动默认只监听本机，可使用 WEB_HOST/WEB_PORT 配置。面板默认关闭；本版本启动时自动将数据库升级至 schema 14，升级前备份数据库。

## 登录与使用

### 节点连通性测试

在“节点管理”点击 **测试连通性**，最长等待 25 秒。节点实际回应探测后显示成功、响应耗时（含轮询等待）和测试时间；超时会提示检查服务、网络与 Agent 版本。下载中同样可以测试，不新增下载任务。测试接口仅管理员可用，沿用会话、Origin 与 CSRF 校验；旧 Agent 需更新后才能回应探测。

### 批量下载

登录后打开“批量下载”，粘贴每批 1–50 个漫画 ID 或配置允许的 HTTPS 链接（沿用 `PROVIDER_DOMAINS`），用换行、空格、英文/中文逗号或分号分隔。确认提交即授权下载，无需逐本点击 Telegram 预览按钮。输入上限 16000 个字符，50 项按原始输入条数计算。

后台逐项查询并入队，前端每 1.5 秒更新结果：等待、正在提交、已入队、跳过、输入无效或失败。批次内重复 ID（包括 ID 与链接指向同一作品）仅处理一次；单项失败不影响后续项目。已入队只是任务提交成功，实际下载/入库进度请在“下载队列”查看。

新任务归属当前登录管理员，进度和结果仅在网页查看，不发送 Telegram 通知；客户端不能指定他人身份、聊天或队列优先级。复用原有全局去重、双队列和归属规则：已下载或进行中的作品不创建新任务；具备白名单组别的发起人命中普通等待任务时只提升原任务，结果说明会标注已提升，原任务归属不变。管理员默认仍进入普通队列，不会因为网页提交自动获得优先权。

每位管理员同时仅可有一个未结束的提交批次，全站最多 8 个待处理/处理中批次，元数据查询串行执行。页面关闭或会话退出不会停止已接受的后台提交，刷新或重新登录会恢复该管理员最新批次。下载任务保存在现有数据库中，无需迁移。

批次结果保存在进程内，完成后保留约 1 小时（最多保留约 100 个批次）；服务重启会清除结果并停止尚未入队项目，不会取消已经入队的任务。重启或提交响应丢失后，可先查看下载队列/下载来源，再重新提交原清单，已有任务会按去重规则跳过。不要把批次结果显示为已入队理解成漫画已下载完成。

### 管理员登录

管理员私聊机器人发送 `/web` 获取登录码，然后在网页粘贴登录。登录码 5 分钟有效、仅用一次，重新获取后旧码失效；会话最长 8 小时，退出、服务重启或新的同账号登录会使原会话失效。只有 TELEGRAM_ALLOWED_USER_IDS 配置的管理员可获取登录码，各接口也重新校验管理员权限。普通用户、白名单、Telegram 群管理员不能登录。

页面支持手动刷新、用户和队列分页、普通/优先队列筛选。“下载来源”打开时自动显示最近 100 条下载任务（含所有状态），按提交时间倒序展示漫画标题、来源 ID、任务编号、发起用户 ID、姓名/用户名、队列、状态和提交时间。时间使用浏览器本地时区。

下载队列按提交时间从新到旧排列，显示本地提交时间，每页 20 条；普通/白名单筛选沿用相同排序。此排序只影响网页展示，实际下载仍按白名单优先、同队列先进先出调度。停留在下载队列时每 5 秒自动刷新，切换页面或退出登录后停止刷新，也可手动刷新。

“负责节点”显示节点名称和 ID：下载、打包、入库及取消收尾期间优先显示当前分配；节点释放后仍保留最后执行节点并标注“最近执行”，重试转交其他节点时更新。节点记录在主控数据库中，重启或删除节点后仍可查询。尚未执行的任务显示“待分配”；升级前已经结束且没有节点记录的任务显示“未记录”，不会猜测历史归属。

用户管理支持按用户 ID、姓名和用户名（可带 @）搜索，先在全部已注册用户中匹配，再按原注册时间排序分页，每页 10 人。输入关键词后点击“搜索”或回车，回到结果第一页；“清空”恢复全部用户。翻页、刷新和封禁/解禁后保留搜索条件；退出登录清空条件。关键词最多 200 个字符，百分号和下划线按普通字符处理。

下载来源支持按漫画标题、漫画 ID、任务编号、用户 ID、姓名和用户名（可带 @）搜索；在全部历史任务中匹配，返回最近最多 100 条结果。清空搜索恢复最近任务，刷新保留当前搜索条件。搜索最多 200 个字符，百分号和下划线按普通字符匹配。仅管理员可访问；Telegram `/who` 查询不变。

封禁、解禁、取消任务、修改开关需要页面二次确认。取消任务保留已发布文件，封禁不撤销 Komga 账号权限。面板不返回 Bot token、Komga 密码、已有节点 Token 或邀请码。节点安装命令包含 30 分钟单次有效凭据，仅管理员可生成；退出登录后清空，勿分享给他人。

会话使用 HttpOnly、SameSite=Strict Cookie，HTTPS 模式启用 Secure；写操作校验 Origin 和 CSRF token，登录入口有全局频率限制。登录码只通过请求体提交，不放入 URL，HTTP 访问日志默认关闭。请勿将登录码分享给其他人。

验证边界：本地未安装 aiohttp/aiogram 时，HTTP 与 Telegram 路由集成测试会跳过；部署后验证管理员登录、普通用户拒绝、退出失效及任务操作。

### 漫画列表与移除

侧边栏“漫画列表”展示本工具记录的漫画，包括未完成和部分保存的漫画，不会扫描或列出在 Komga 中手动添加的其他作品。支持标题、来源 ID 搜索及每页 20 本分页，显示已保存章节数、记录大小和任务状态；文件统计来自入库记录，外部直接修改文件后不保证实时反映磁盘情况。

点击单本“移除”并确认，会永久删除主控漫画库中该漫画记录的 CBZ 章节文件；不会递归删除整个目录、其他文件或历史临时缓存。排队、下载、重试、磁盘暂停和取消收尾中的漫画拒绝移除，需先到下载队列取消并等待节点释放。服务端始终重新检查，不依赖按钮状态。

移除后从列表隐藏该漫画，清空章节文件校验和与 Komga 引用，保留原下载任务、来源用户及通知历史，并允许再次提交同一本漫画。重新下载的任务仍遵守去重和双队列规则。已经缺失的文件允许清理记录；如果部分文件删除失败，漫画记录仍保留，可修复权限后再次移除。

文件删除后主控请求 Komga 扫描目标库，扫描异步完成，Komga 展示更新可能有延迟。扫描请求失败时页面明确显示“文件已移除，请手动扫描”，文件不会恢复。自定义 KOMGA_COMMAND 适配器需支持 `scan` 操作，协议见 PROVIDER_PROTOCOL.md。

本版启动将数据库升级到 schema 11，记录最后移除时间，用于保留历史并允许重新下载；升级前备份，回滚旧版需恢复备份。无需升级 Agent。

### 举报管理

侧边栏“举报管理”默认展示待处理举报，每页 20 条，支持按漫画标题、漫画 ID 或举报用户 ID 搜索，筛选待处理、已移除漫画、已忽略及全部记录。页面展示举报编号、漫画、举报者、提交时间、处理状态、处理人及时间；时间使用浏览器本地时区。

- **查看漫画**：跳转漫画列表并按漫画 ID 搜索。
- **忽略**：确认后关闭该条举报，保留漫画文件，不影响同一本的其他待处理举报。
- **移除漫画**：确认后删除已保存章节，关闭该漫画的全部待处理举报并请求 Komga 扫描。未结束任务或文件删除失败会阻止处理，举报继续待处理；文件删除成功而 Komga 扫描失败时，举报仍记为已处理，页面提示手动扫描。

在漫画列表直接移除也会关闭对应待处理举报。处理状态与 Telegram 消息投递状态分开保存；已发送提醒不会自动将举报设为已处理。处理完成后停止尚未发出的提醒；已经发送中的提醒可能仍会到达。Telegram 消息不提供审核按钮，管理员通过 /web 登录处理。举报列表和写操作沿用管理员认证、Origin 与 CSRF 校验。

### 网页批量任务静默

新提交的网页批量任务在入队时保存静默标记，不发送 Telegram 进度、完成封面、失败或取消通知。标记随任务持久保存，重启、自动重试及原任务的重试继续静默。用户归属、双队列、去重和网页结果照常保留。

Telegram /jm 及私聊预览确认的任务仍在原聊天推送；批量提交遇到已有任务只按去重/提升规则处理，不改变原任务通知策略。旧版没有保存可靠的批量任务来源，因此升级前已有任务保持原通知策略，不根据用户 ID 或消息 ID 猜测并修改。

本版迁移至 schema 14，新增任务最后执行节点记录和提交时间排序索引，并保留举报处理状态、处理人/时间以及任务通知标记。旧举报默认待处理，旧任务默认保留通知。升级前备份数据库，仅更新主控，无需升级 Agent。
