# 2026-10-17 代码审查与修复

本轮在现有未提交改动基础上审查文件发布、任务状态、外部适配器隔离及安装脚本。没有部署到 VPS，没有变更用户要求的 latest 镜像和默认关闭磁盘阈值检查设置。

## 已修复

- 文件名按 UTF-8 字节截断，避免中文标题导致 Linux 文件名超限；数据库内已有路径保持不变。
- 临时图片识别仅接受标准页码文件名，忽略 SDK 中断残留；重复完整页明确失败，不继续重复下载。
- CBZ 打包沿用配置的字节数和像素限制；临时 CBZ、SDK 解码输出和配置文件使用独占随机临时文件，避免固定临时路径覆盖。
- 拒绝读取符号链接图片；原子发布不覆盖已存在的漫画文件。
- 排队、等待重试和磁盘暂停任务可立即取消并写入终态通知，不再等待 worker 空闲。
- 同一漫画由另一用户提交时不返回已有任务信息，避免跨用户泄露任务 ID 或状态。
- 数据源进程不再继承 Telegram/Komga 环境凭据；Komga 进程不继承 Telegram/JM/数据源配置。仅是凭据最小化，不是第三方代码沙箱。
- SDK 写满磁盘被归类为 DISK_FULL；畸形页列表和 error 对象按协议错误处理。
- 从数据库恢复的页列表也校验页数、页序；shell 脚本固定 LF 换行。

## 验证

使用本机 Python 3.12 与 Pillow 运行 unittest：核心 26 项、适配器 18 项，共 44 项。新增回归涵盖中文长文件名、SDK 中断残留、立即取消、跨用户提交、打包限制、子进程凭据隔离、磁盘错误及安全配置写入。源码编译和 shell 语法也需通过。

## 仍存在的限制

- 未执行真实 Telegram/JMComic/Komga 和 Docker/VPS 联调；上游兼容和依赖安全版本不因离线测试而得到确认。
- 图片下载流量仍由 SDK 控制，字节限制在下载完成后检查；不等于流式磁盘配额。
- 打包和完整性检查同步执行，大章节可能延迟 Bot 响应；后续可改为带进度及取消协议的独立打包进程。
- 手动重试新建任务，目前只复用已发布章节；旧任务尚未发布的临时页不会跨任务复用。成功任务临时图片仍需人工清理。
- 依赖尚未完整锁定；未执行网络依赖漏洞扫描。不能据此宣称“所有漏洞已清除”。
