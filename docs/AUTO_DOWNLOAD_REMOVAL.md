# 自动下载功能移除记录

日期：2026-10-24。代码与离线回归完成，未部署到 VPS。

## 移除范围

- 删除定时计划向导、调度器、自动通知循环、标签发现与点赞排序、自动任务内容筛选及五分钟等待逻辑。
- 删除自动下载的服务、领域模型、适配器扩展、配置项、tzdata 依赖及旧功能说明/测试。
- 管理员菜单、帮助、服务状态与健康检查不再展示或依赖调度器。
- 旧命令、旧菜单文本和 `sched:` 按钮只回复“功能已移除”，不会恢复计划、请求来源或提交任务。发送 `/start` 可刷新客户端键盘。
- 保留按 ID/链接预览、确认下载、查询、取消、失败重试、标签元数据、CBZ、Komga 入库及用户/阅读账号管理。

## 数据库与历史数据

数据库升级到 schema 6。schema 1–4 直接进入手动队列版本，仅增加稳定 FIFO 序号，不再创建自动计划表。

schema 5 在一个事务内：

1. 将旧自动来源的未完成任务改为 CANCELLED，记录 AUTO_DOWNLOAD_REMOVED；其待发送任务通知改为 SKIPPED。
2. 删除计划、批次、候选、确认、草稿、自动通知与自动去重表，以及活动下载标记和等待时间。
3. 移除任务的 origin、schedule_run_id、policy_version 字段，保留 queue_sequence。
4. 保留所有任务记录和快照、章节关联与原文件路径、已完成/失败/取消任务的状态，以及用户、邀请码和 Komga 账号。

迁移不操作漫画文件，不删除已入库内容或部分下载文件。未完成手动任务保持原状态并按既有恢复逻辑继续。历史失败任务只有在用户显式发起重试时才生成普通手动任务。

迁移出错会回滚并关闭连接，不启动部分升级的数据库；重新启动 schema 6 不重复清理或改写任务。旧的自动计划数据已删除，回滚必须恢复升级前备份，不能仅替换旧镜像。
